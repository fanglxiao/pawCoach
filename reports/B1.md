# B1 SuperAnimal 安装 + 关键点推理

- 预计工时：2～4h（实际约 1h，装环境 + 下权重 + 跑通 + 出图）
- 验收命令：
  ```bash
  export https_proxy=http://127.0.0.1:7892 http_proxy=http://127.0.0.1:7892   # 下权重要走代理
  .venv-b/bin/python scripts/b1_pose_probe.py data/raw/dog2.mp4
  .venv-b/bin/python scripts/b1_plot_keypoints.py data/raw/dog2.mp4 \
      data/pose/dog2_superanimal_quadruped_rtmpose_s_ssdlite.h5 reports/pose_keypoints_sample.png
  ```
- 验收结果：**通过**
  - SuperAnimal-Quadruped 装上并跑通，用的是首选路径（deeplabcut），没有退到 mmpose。
  - `reports/pose_keypoints_sample.png` 已生成。8 帧里关键点基本都落在狗身上：头部（红）、四肢（蓝、橙）、脊背（绿）位置合理，狗站立、低头、坐着的几个姿态都跟得上。
  - 推理结果在 `data/pose/dog2_superanimal_quadruped_rtmpose_s_ssdlite.h5`：518 帧 x 39 个关键点，每点有 x、y、likelihood。
- 基线指标（只记，不设门槛；样本是 `dog2.mp4` 一段，17.3 秒、518 帧）：
  - 整体平均关键点置信度 0.50，置信度大于 0.5 的关键点占 49.3%。
  - 518 帧里没有一帧是「所有关键点置信度都小于 0.3」，也就是每帧都检测到了狗。
  - 置信度最高的是眼睛、上颌、鼻子、前爪（0.61 到 0.67）。
  - 推理耗时：权重已缓存时，17.3 秒视频（518 帧）用时 77.9 秒，约 4.5 倍实时，设备是 Apple 芯片 MPS（`device="auto"`）。按这个速度，60 秒视频只姿态一项就要约 4.5 分钟，超过 D3 的「全流程 3 分钟」目标。D3 之前要想办法：降到 10fps 抽帧推理、换更小的检测器，或把推理放到 GPU 服务器上。
- 遗留问题：
  - 视频开头（第 0 秒）狗在画面边缘，关键点有明显偏离，有一个点跑到了画面外。第 7.4 秒（狗被手挡住）关键点也有错位。B2 的规则要靠置信度过滤这类帧，不能直接信。
  - 第 0 秒的图里，朝向画面右侧的狗是侧面，关键点只落在部分身体上。侧面坐姿的判定是否可靠，要等 B2 在有侧面坐姿的视频上验证。`dog2.mp4` 大部分是正面，正面看不出臀部高度，B2 的「臀、膝、肩相对高度」规则在正面视角下可能不好用。
  - 只试了 `rtmpose_s` + `ssdlite` 这一个最小组合。效果不够再换 `hrnet_w32` + `fasterrcnn_resnet50_fpn_v2`（权重在同一个 HuggingFace 仓库里），代价是速度。
  - `dlclibrary` 下载权重时会打印很多关于配置字段的警告，不影响结果。
- 环境要点（已写进 `requirements-b.txt`）：
  - deeplabcut 3.0.2 只支持到 Python 3.12，本机 `.venv` 是 3.13，所以阶段 B 单独建了 `.venv-b`（Python 3.12，用 uv 装）。`.venv-b` 已加入 `.gitignore`。
  - 安装用了代理，deeplabcut 连同 torch 2.15 约 1.5 分钟装完。
  - 权重文件在 `.venv-b/lib/python3.12/site-packages/deeplabcut/modelzoo/checkpoints/`：`rtmpose_s` 23 MB，`ssdlite` 8.7 MB。
- 下一步（调准）：B2 写 `SuperAnimalPoseExtractor`，用关键点相对高度和角度判坐、站、卧，并做时序平滑。
